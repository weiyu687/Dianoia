# 学情分析与教学资源共享设计

状态：负责人已于 2026-11-23 确认产品范围与技术路线；首版实施记录更新于 2026-11-24。

## 1. 产品目标与边界

学情分析面向教师，允许上传成绩、作业、考勤等 CSV、XLS、XLSX 表格；每种表格的列名和排列方式可能不同。系统通过字段映射和数据预览，把教师确认的记录整理成统一指标，提供班级当前概览、历史变化、单个学生档案，以及后续教学/学习计划草稿和资源推荐。它用于辅助教师判断和安排教学，不自动给学生定级、排名、处分或发布计划。

本功能不依赖先建独立学校管理端。学校管理端停止产品扩展，现有入口仅保留历史兼容，不作为新增功能依赖；教师、学生应用入口各自独立。学情分析复用当前教师任课课程和已录入班级；单个导入批次可以对应一个班级，也可暂不指定班级。学生账号身份源由独立学生端接入既有学校 SSO 或学校身份系统确定，不新增管理端账号开通流程。

平台级共享资源池是四类教师成果的统一学生发现入口：PPT、在线题库、思维导图、数字课程。教师明确发布后，学生可用课程名、学科、年级/专业、学期、章节、主题词、资源类型等条件搜索。发布人、发布时间、摘要、关键词、来源课程及当前发布版本可见。学生只能访问已发布快照；草稿、教师学情数据、班级统计、其他学生身份及个体计划始终按教师或本人权限隔离。下架或撤回后，学生端搜索和打开接口都立即检查状态。

## 2. 主要工作流

1. 教师上传 CSV、XLS 或 XLSX；XLSX 可选择工作表。当前单文件上限 20 MiB、单工作表最多 50,000 行和 100 列。文件名不依赖字段名，系统建议学生标识和指标字段，由教师修订。
2. 页面显示前 12 行样例。教师为每个批次命名，选填班级/学期，配置学生标识、姓名、日期、活动、知识点、满分和最多 12 项指标，并选择成绩、作业、考勤、数值或分类类型。缺失值不转为 0；未知状态按文本类别统计。
3. 映射预览按“有学生标识且至少一项指标非空”校验行，显示有效行、异常行号和原因。教师确认后将任务放入独立 worker；同一文件可以作为不同批次重复导入，不会自动覆盖历史记录。批次可删除，失败任务可重试。
4. 成功导入后进入学情大屏，按课程、班级、批次和指标查看覆盖人数、指标均值/出勤率/完成率、成绩分布、分类构成、近期批次趋势与学生记录。点击单个学生可查看最近 500 条已导入指标记录。无满分或口径不一致时不绘制百分制分布；历史成绩只连接可按同一满分标准换算的批次。
5. 教师查看系统生成的统计发现，选定教学目标和需要支持的学生/班级后生成计划草稿。资源推荐只引用平台四类资源池中的真实已发布内容，并显示推荐依据。教师编辑并确认后，计划可留作教师工作记录；若面向学生发布，则仅向指定学生本人显示。

## 3. 分析模板与大屏

“模板”拆为两类，避免把导入格式和图表布局混成一个设置：

- **字段映射模板**：保存字段角色、表头别名、日期/分数解释、状态值映射和默认分析范围；预置成绩、作业、考勤三类模板，教师可保存个人模板。模板不保存学生行数据。
- **大屏布局模板**：预置“综合班级学情”“成绩与测验”“作业与考勤”布局。教师可选择显示指标卡、趋势、成绩分布、类别构成和学生记录面板，并保存、删除个人布局；个人模板只保存面板配置。首版不开放通用 SQL 或任意脚本。

大屏首屏建议包含：当前班级与数据覆盖范围、有效人数/记录数、导入质量提示、最近时间、指标卡片、变化趋势和可执行提醒。按字段可用性动态展示：

| 视图 | 默认内容 | 仅在数据充分时显示 |
| --- | --- | --- |
| 班级当前 | 成绩均值/中位数/分布；提交率；出勤率；有效样本数和缺失数 | 教师设定及格阈值后显示达标比例；题目/知识点分析需有题目得分或知识点标签 |
| 历史 | 同一课程、班级和可比指标的时间趋势；当前与上期对比 | 只有评分量纲/满分一致或已归一化时才比较成绩；跨学期需教师确认班级与口径可比 |
| 学生 | 指定学生的成绩、作业完成、考勤时间线与资料覆盖情况 | 知识点掌握图需有题目级或知识点级记录；样本不足时标注“数据不足”，不推断能力 |

不提供默认公开排名。教师可以看班级分布与个人档案，不向同班学生展示同伴成绩。每张图都标明指标定义、时间范围、有效样本数、缺失口径和来源批次；不以无数据生成“看起来完整”的智慧大屏。

## 4. 数据模型与导入策略建议

建议采用追加式导入批次和标准化观测事实，而不是把原始表格直接塞进一列 JSON：

- `LearningImportBatch`：上传者、课程/班级、学期标签、原文件名和私有存储键、SHA-256、表/表头选择、映射模板版本、校验统计、状态、创建与确认时间。
- `LearningObservation`：批次 ID、学生内部引用（可空，待教师匹配）、发生日期、活动/作业名、指标 key、数值/类别值、满分或单位、知识点标签、来源行号。一个宽表学生行可规范化为多个学生-活动-指标观测。
- `AnalyticsMappingTemplate`、`AnalyticsDashboardTemplate`：分别保存字段映射和大屏布局，不混存学生记录。
- `TeachingPlan` / `StudentLearningPlan`：来源批次和筛选快照、教师确认的目标/行动、资源池项目引用、状态、创建人/接收学生、版本及审计时间。
- 共享池发布目录：稳定的资源类型和资源版本引用、标题/摘要/课程/学科/学期/章节/关键词/封面、发布教师与发布时间、发布状态。每次发布产生不可变快照；撤回或新版本都保留可审计的发布历史。

原始上传文件与解析结果仅限该课程任课教师访问，下载/删除有权限检查；支持删除批次及其派生观测。建议配置保留期和可审计清理任务。分析接口按当前教师的课程/班级授权；学生计划只向创建教师及被指定学生开放。文件上传限制 CSV/XLS/XLSX，校验扩展名和 MIME、文件签名、大小、工作表/行列数；不执行宏、不读取远程 URL。含公式的单元格不执行公式，缺少缓存值时提示教师提供值或修正文件。

## 5. 计划生成与资源推荐

首版用可解释统计和规则，不训练“学情预测”模型。数据刚开始由不定格式文件导入，通常缺少按题作答、稳定知识点标签和足够长的个人时序；深度知识追踪研究依赖学生与课程活动的序列记录，不能把一次成绩表伪装成掌握度预测。[Deep Knowledge Tracing](https://proceedings.neurips.cc/paper_files/paper/2015/hash/bac9162b47c56fc8a4d2a519803d51b3-Abstract.html)

首版链路：

1. 后端先按教师定义的阈值、变化、完成率等计算可核对的事实，并展示样本数与范围。
2. 规则建议“可进一步核查的教学关注点”，不自动诊断学生。教师选择关注点后，AI 只生成计划文字草稿；输入使用聚合指标、脱敏代号和教师选中的资料/知识点，不把姓名、学号、原始表格行或其他学生数据发给模型。
3. 推荐先以明确规则从共享目录过滤已发布资源，例如课程/学科匹配、知识点/章节标签、题库难度或课程类型；展示“匹配到的标签/目标”作为原因。教师可移除或替换推荐。没有合适资源时明确显示未找到，不编造链接。
4. 计划须经教师编辑确认。班级教学计划归教师；个人学习计划只发布给选中的学生本人。模型文字和规则都不是自动成绩、录取、分层或纪律决策。

学习分析仪表板的研究支持把数据呈现与教师可执行的反馈结合，但研究者也指出不同学校情境和具体功能仍需实证验证；因此首版以教师控制、指标可追溯和建议可编辑为产品约束，不承诺因大屏或 AI 自动提升成绩。[LA Cockpit 2024 干预研究](https://doi.org/10.18608/jla.2024.8399) · [K–12 情境化教师仪表板设计研究](https://doi.org/10.1111/bjet.13383)

## 6. 学生共享资源池

四类内容共用检索与发布契约，但保留各自编辑器和版本模型：

- 支持资源类型、课程、学科、适用学段/专业、学期、章节、主题词、教师、发布时间、更新时间、摘要、封面及可选资源范围筛选。
- 教师在内容页面选择“发布到学生资源池”，确认元数据、预览学生可见内容并发布；发布人和发布时间自动记录，不接受前端覆盖。
- 学生端面向所有已登录学生展示平台级已发布资源。学生不必拥有教师的课程权限即可搜索公开资源；打开时仍检查发布状态、资源版本和访问规则。
- 题库共享为已确认的发布版本；答案按题库当前自主练习策略展现。其他资源只公开内容，不公开私人资料挂载、内部提示词、未发布稿和教师备注。
- 建议 MVP 先支持发布/更新/下架、统一检索、详情和固定版本打开；点赞、评论、个性化排序和站外分享不纳入首版。

## 7. 建议技术选型

以下是建议方案，需负责人确认后才安装依赖或写业务代码。依赖的具体版本在批准实施时再按锁文件核实并登记。

| 层 | 建议 | 候选对比与原因 |
| --- | --- | --- |
| 大屏可视化 | Apache ECharts 6.1.0 + Vue 3 按需组件 | 支持常用统计图、交互提示及响应式展示；按需注册折线、柱图、饼图及 Grid/Tooltip/Legend，避免引入 BI 服务和不必要的全量图表代码。dataset/transform 可用于后续可配置分析。[ECharts Data Transform](https://echarts.apache.org/handbook/en/concepts/data-transform/) |
| CSV/XLS/XLSX 解析与轻量汇总 | pandas 3.1.1 + 已有 openpyxl + xlrd 2.0.2 | pandas 提供统一 DataFrame 解析；openpyxl 读取 XLSX、xlrd 仅读取旧 `.xls`。CSV 自动尝试 UTF-8 BOM 和 GB18030。公式不执行，读取工作簿保存值。版本锁定在 requirements 文件。[pandas.read_excel](https://pandas.pydata.org/docs/reference/api/pandas.read_excel.html) · [xlrd 支持边界](https://pypi.org/project/xlrd/) |
| 导入工作 | FastAPI 上传 + SQLAlchemy 批次状态 + 独立 CPU worker | 两阶段预览/确认，事实分批写入，可重试；不新增 Redis/Celery。worker 使用 `python -m app.learning_analytics.worker` 运行。 |
| 持久化 | 当前 SQLAlchemy 2 + Alembic；本地 SQLite、生产 PostgreSQL | 关系表保存批次、映射、观测、计划与审计；原件进私有文件存储，后续可迁移 S3 兼容对象存储。沿用现有版本迁移，不把 JSON 当作唯一统计存储。 |
| 生成式 AI | 当前 OpenAI-compatible LLM 服务 | 仅生成教师审核的解释/计划文本，不负责解析每个未知列、不替代确定性统计、不输出未经查证的数值；默认仅使用脱敏的聚合数据。 |
| 学习模型 | 首版不引入 DKT、分类器或预测 API | 先积累纵向、结构化、质量有标记的数据并验证指标定义；满足数据充分性和研究伦理/隐私条件后再单独讨论预测或个性化算法。 |

## 8. 可行性、风险与验证样例

复用现有课程/班级关系、`Student` 名册和教师登录，教师端可以先落地分析闭环；但现在模型的 `Student` 只有学号/姓名、没有学生用户关联，课程没有正式学期字段，也未实现学生登录。因此本组件不依赖学生端认证即可支持教师分析；学生可访问资源池和接收个人计划必须等学生身份与独立入口方案完成后验收。

技术验证样例：

1. 同一班的成绩宽表（中文/英文表头、不同列顺序、缺考、百分制与不同满分）、作业提交长表、考勤枚举表；可保存映射模板，修改模板不会改变已确认的历史批次。
2. CSV UTF-8 BOM/GB18030、XLS 和多工作表 XLSX；日期、公式空缓存、空值、重复行、未知列、未匹配学生等都在预览中可见，坏行不会被悄悄统计。
3. 同一学生多批次记录生成可比趋势；不匹配满分的考试不能直接做原始分数趋势，经过确认的标准化分值可比较。
4. 小样本、缺失字段和无知识点标签时，大屏隐藏不成立的指标；计划显示统计来源和限制。
5. A 教师无权读 B 教师的原始批次或个体计划；学生 A/B 只能读取自己的计划及全平台已发布内容；下架资源从搜索和详情同时失效。
6. 发布目录包含四种资源的真实版本，检索按题库标题、PPT 学科、章节和关键词可用，发布人/时间可追溯。

## 9. 隐私与学术依据

学生成绩、考勤及作业记录可关联到自然人，按个人信息处理设计：目的和范围明确、最少字段、最短保留、访问审计、本人计划严格定向，并提供删除/更正流程；不把学生记录放入公共资源池。对未满十四周岁学生，《个人信息保护法》将其个人信息列为敏感个人信息，处理需特定目的、充分必要和严格保护，并涉及监护人同意等要求。教育部已发布 JY/T 0643—2025《智慧教育平台 个人信息保护通用要求》。部署前由学校明确数据控制者、处理目的、告知/授权依据、模型服务处理约定和保存周期；该文档不是法律意见。[个人信息保护法](https://www.miit.gov.cn/zwgk/zcwj/flfg/art/2022/art_04a0f1fb5df244e39688fd5372623a8d.html) · [教育部 JY/T 0643—2025 发布通知](https://www.moe.gov.cn/srcsite/A16/s3342/202507/t20250731_1200912.html)

## 10. 首版验收范围

- 上传和校验 CSV/XLS/XLSX；教师映射、预览、确认、保存并管理批次。
- 字段映射模板与三类大屏布局可创建/复用；班级当前、历史和单学生视图按数据情况展示。
- 指标可追溯，缺失、样本量和可比性清晰；支持数据修正/删除和隔离。
- 基于明确统计生成可编辑的教学计划草稿与经教师确认的真实资源推荐。
- 教师可以发布包含发布人和发布时间的四类资源版本；学生资源池依赖后续学生入口，不将“教师已发布”伪称为学生端已可用。
- Agent 首版工具限制为只读分析查询、解释指标和创建待审核计划草稿，不提供自动发布或批量改动学生记录。

## 12. 学生数据边界与后续决策

当前学生记录用于教师可授权的统计和支持性计划，不作为预测、评价、处分或自动分层输入。个人计划仍为教师草稿。正式面向学校运行前，需与学校确认学生身份接入、数据告知与处理依据、留存周期、学生查阅/更正/删除途径，以及模型服务的数据处理条件。统计大屏研究指出设计与干预需结合学校情境验证，不代表单一指标可推断学习能力。[Deep Knowledge Tracing](https://proceedings.neurips.cc/paper_files/paper/2015/hash/bac9162b47c56fc8a4d2a519803d51b3-Abstract.html) · [教师仪表板干预研究](https://doi.org/10.18608/jla.2024.8399) · [教育部 JY/T 0643—2025](https://www.moe.gov.cn/srcsite/A16/s3342/202507/t20250731_1200912.html)
