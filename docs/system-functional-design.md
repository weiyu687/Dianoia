# 智能教育平台功能设计

状态为 v0.3，更新于 2026-11-12。

## 1. 建设范围

平台采用前后端分离架构，面向学校管理人员、教师和学生。先建设简易管理端和教师端，教师端验收后再启动学生端开发。首期按单校试运行设计，基础数据归属学校，教师权限限定在被分配的课程和教学班。

首期在管理端录入或导入模拟数据。教师端使用这些数据完成备课、内容生成、作业批改和学情分析。学生端启用前，教师可导入已有作答记录，使用教学任务及其版本完成批改和统计。

学校管理端和教师端使用独立入口。教师工作台提供亮暗切换。资料库和教案各有管理列表，上传资料和新建教案从各自列表进入。教师 Agent 使用独立对话页面。

## 2. 角色与权限

| 角色 | 首期职责 | 数据访问范围 |
| --- | --- | --- |
| 学校管理人员 | 管理教师、学生、课程、教学班、班级名单和任课关系 | 本校基础资料和管理记录。教师备课草稿、答卷及评语需要独立的业务授权 |
| 教师 | 准备教学资源，生成教学内容，维护试卷和作业，批改并查看学情 | 自己的备课材料，以及所负责课程和教学班中有权限访问的材料与记录 |
| 学生 | 学生端启用后查看教学任务、提交作答、查看已公开的反馈 | 自己所属教学班内已发布的内容，以及本人的作答与已公开反馈 |

## 3. 学校管理端

1. **教师和学生档案**。手工录入、编辑、停用，支持按模板批量导入。教师工号和学生学号在各自的学校及人员类型范围内唯一。教师账户由管理人员开通、停用或重置登录凭据。学生档案可先用于编班和匹配答卷。
2. **教学关系**。维护学期、课程与教学班，分配任课教师，增减或导入班级名单。教师登录后按任课关系看到课程与班级。
3. **导入校验和管理记录**。提交前预览新增、更新和失败行，展示原因。重复导入同一批数据不会增加重复档案。停用人员或变更任课关系保留既有教学记录，并记录操作者与操作时间。

验收场景为管理人员建立一门课程、一个教学班、一名教师和若干模拟学生，分配任课关系。教师登录后能看到课程和名单，其他无任课权限的教师无法访问该班级资料。

## 4. 教师端

### 4.1 课程工作区与教学资料

教师按学期、课程和教学单元管理资料与成果。教师上传课程大纲、教材节选、讲义、习题等资料，选择某次生成可使用的范围。生成结果保留关联的资料版本和生成任务记录。对于缺少资料支撑的生成内容，界面提示教师核实。

资料库支持上传、列表、搜索、重命名、下载原件、删除、预览与多级目录校对。目录节点有起止页。上传后先校对，确认后进入可选资料范围。资料暂按文本层提取。

验收时，教师能在同一课程下找回资料、历史生成结果和已确认版本，并能从生成结果查看所选资料。

### 4.2 教案生成

教师设置主题、授课对象、课时和教学目标，选择参考资料。按资料章节或页码取材生成的草稿涵盖教学目标、重难点、教学活动、时间安排与课堂评价。教师可在分页编辑器中直接修改正文并保存。

教案管理支持列表、重命名、复制、归档、恢复与删除。教师可上传、预览、重命名和删除 DOC 或 DOCX 模板。新建教案可以使用空白页、使用模型生成草稿，或加载 Word 模板的完整内容与样式。使用模板时，教案独立保存。正文中可以使用多级标题。编辑器直接调用模型处理选区重写与光标续写，快捷键为 `Alt+\`。教案以 PDF 预览，支持导出 DOCX、PDF 和旧版 DOC。

教师可通过工具栏在光标处插入本地 PNG、JPEG 或 GIF。图片嵌入教案文档，随文档保存和导出。

验收时，教师能从空白文档或学校 Word 模板创建教案，修改正文和表格、插入图片，保存后重新打开并核对 PDF 预览与导出。

### 4.3 知识框架生成与梳理

教师从教学资料提取课程、章节、知识点及其层级，补充知识点描述与资料来源。教师可合并重复项、调整层级、移动知识点、确认知识框架版本。已确认的知识点可用于标注题目和汇总学情。

验收时，教师能从大纲和讲义建立知识框架，调整一个知识点的归属并确认版本。引用已确认知识点的题目仍可追溯到对应记录。

### 4.4 知识架构图生成

基于选定的知识框架生成图形视图，支持查看层级、先修和关联关系。教师可编辑节点及关系，保存图稿并导出图片。对会引入循环先修依赖的编辑提供提示。

验收时，教师能从已确认的框架生成一张图，调整关系后保存并导出，图稿可追溯到生成时采用的框架版本。

### 4.5 课件 PPT 生成

教师可从教案、知识框架或教学资料生成分页大纲，调整页序和版式，再生成含标题、正文、图表与演讲备注的可编辑课件。教师可更新选定页面并导出 PPTX。

验收时，教师能打开导出的 PPTX，编辑文字并确认页序、演讲备注与所选大纲一致。

### 4.6 数字课程与数字人

面向高校慕课录制场景。教师在数字课程专用页面上传 PPT 或选择已生成的课件版本，按页生成口播稿，编辑分段脚本与字幕。教师选择预置数字人，或上传经授权的形象素材，并选择预置语音或上传本人或授权的参考语音。语音组件选型时验证单段参考音频的零样本合成和少量样本适配的适用条件。教师先预览片段，确认后提交整课合成任务，可查看进度、失败原因及重试结果。完成后导出 MP4 视频与字幕文件，由教师自行分发。

验收时，教师能上传一节课的 PPT 并生成逐页口播稿，上传经授权的形象与参考音频，预览并修改其中一个片段，最终导出含数字人、旁白和字幕的成片。

### 4.7 试卷生成与作业设置

教师可从题库选题或按知识点、题型、题量、分值和难度要求生成新题。组卷时检查题数与分值，提示重复题和答案缺失。生成题目进入待审核状态。教师确认题目、参考答案及评分规则后保存试卷，可分别导出学生用卷与教师答案，或将选定版本作为作业。

验收时，教师能为指定知识范围生成试卷，修订题目并确认总分、题型结构及评分规则。修改题目后可保留之前发布或用于批改的试卷版本。

### 4.8 作业批改

学生端上线前，教师导入按学号、题目和教学任务版本匹配的电子作答记录，检查缺交、无法匹配和重复提交。客观题按确认的答案计分。主观题生成分项评分建议、答卷依据和评语草稿，教师可逐份复核并确认成绩与反馈。改分记录保存操作者、时间及变更前后的分数。

验收时，教师能导入一个班的作答，处理一条匹配异常，核查客观题得分，修改一条主观题评分建议，并导出确认后的成绩与评语。

### 4.9 学情分析与讲评

教师按班级、学生、作业和知识点查看提交率、得分分布、题目正确率及高频错误，能够从班级统计查看相关题目和有权限访问的作答。统计展示有效样本量、缺交和待批改数量。基于教师确认的批改结果生成讲评提纲与补练建议，由教师选择和修订。

验收时，教师能定位某次作业中正确率较低的知识点，核查样本和关联答卷，确认改分后的统计结果随之更新。

### 4.10 教师 Agent 对话窗口

教师可以直接使用各功能页面，也可以从教师工作台打开独立的 Agent 全页对话。对话显示当前课程上下文。当操作所需的章节、资料或作业范围存在歧义时，Agent 先让教师明确范围。Agent 执行真实的业务操作，并将任务状态、成果链接或失败原因返回对话。

| 功能 | Agent 可执行的操作 | 功能页面承载的操作 |
| --- | --- | --- |
| 教案 | 已支持读取列表与正文。按目标、课时和资料生成，以及修改教案，待接入 | Word 分页编辑、模板管理、版本保存与导出 |
| 知识框架与架构图 | 从已选资料提取知识框架，基于选定版本生成架构图 | 层级与关系编辑、图稿预览和导出 |
| 课件 PPT | 使用教案或知识框架生成课件草稿及可编辑 PPTX | 调整页序和版式、逐页编辑 |
| 试卷 | 根据知识点、题量和分值要求生成试卷草稿 | 逐题审核，确认评分规则与试卷版本 |
| 作业批改 | 对已导入且匹配成功的指定批次启动批改、查询进度 | 导入与匹配校验，核查主观题得分、确认成绩及公开反馈 |
| 学情分析 | 查询授权范围内的统计，生成讲评提纲与补练建议 | 查看统计明细、筛选、追溯到题目和答卷 |
| 数字课程 | 提供数字课程页面入口 | 上传 PPT、生成和编辑口播稿、上传形象及参考语音、预览、渲染与导出 |

功能页面和 Agent 共用业务校验、权限、任务与成果记录。由对话创建的草稿进入对应功能页面，教师在页面编辑和确认。对话可串联多个生成工具，每一步均记录所用资料和版本。数字课程的制作流程整体由专用页面驱动。

验收时，教师能在同一段对话中基于已选资料生成教案与 PPT 草稿，查看进度，打开 PPT 功能页接着编辑。对话能查询本班已确认的统计。跨班查询按任课权限拦截。数字课程请求可引导教师打开专用页面。

## 5. 教学成果与两端衔接

- 生成过程区分排队、处理中、成功与失败。生成成功的内容先保存为草稿，教师确认后产生可引用版本。教师可选择使用已有版本，并在原草稿基础上继续编辑。
- 学生端后续读取教师发布的教学任务与指定内容版本。每次作答关联学生、教学班、教学任务和任务版本。批改确认与反馈公开分别记录，由教师决定反馈何时可见。
- 教师端首期可创建教学任务和导入作答，并导出确认后的批改结果。学生端启用后，在线提交进入同一批改流程。
- 教学资料和学生记录按角色、学校及课程授权。对任课分配、内容发布、成绩变更等业务动作保留记录。耗时的导入、生成和合成任务提供进度、失败反馈及重试，重试时保留已完成的成果。

## 6. 建议开发顺序

1. 简易管理端、登录与权限、课程工作区和资料管理。
2. 教案生成页面与教师 Agent 对话窗口，验证两种入口共用业务操作和生成结果。
3. 知识框架、知识架构图、PPT、题库、试卷与作业设置、作答导入、批改及学情分析。逐个接入对应的 Agent 工具。
4. 数字课程与数字人，复用课件、脚本编辑和生成任务能力。
5. 完成教师端验收后启动学生端。

各组件可独立验收。数字课程场景如需提前验证，可在课件产出可用后安排一节课程的试制。

## 7. 组件选型、开发与验收

- **选型讨论**。每个组件开发前，先确定输入、预期输出、候选方案与验证样例。以调研当时的主流方案为候选，使用官方文档、原始论文或公开评测作为依据，比较效果、中文与目标学科适配、成本、延迟、部署方式、许可、数据处理方式与维护情况。对影响真实使用的关键问题安排小样验证，和项目负责人确认后更新[技术栈与选型记录](technology-stack.md)。
- **工程规范**。待架构和技术栈确认后，将模块边界、接口契约、代码风格、变更审查和发布规则写入工程规范。按可独立验证的变更提交，保持接口行为一致，对权限、版本、输入校验、失败恢复和错误日志作明确处理。
- **验证与验收**。保留关键业务链路、权限隔离、成绩及统计正确性、任务失败恢复所需的自动化验证。每个生成类组件保留代表性输入和验收步骤，功能体验及教学产出由项目负责人验收。
- **日志与 GitHub**。持续记录已完成事项、设计与选型决定、验证结果和未决事项。按独立变更提交代码与对应文档，持续同步至 [weiyu687/Dianoia](https://github.com/weiyu687/Dianoia)。

## 8. 架构与待确认事项

前后端与 Agent 框架方向已记录在[架构设计讨论稿](architecture-design.md)。首版范围包含电子答卷批改及慕课视频文件导出。

待确认用于首轮验收的高校课程、授课对象和可使用的课程资料。当前以一门课程、一个教学班作为端到端验收场景，题型覆盖客观题和可按评分规则复核的主观题。
